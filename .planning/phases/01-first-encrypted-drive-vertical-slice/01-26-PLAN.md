<objective>
Close the SC-04 WinFsp directory metadata gap: populate real timestamps from the encrypted store, support Windows wildcard patterns in directory enumeration, and emit directory-change notifications so Explorer and PowerShell show a usable per-user protected drive on LAB-CLIENT01.

Purpose: The only remaining Phase 1 blocker is UAT SC-04, where `mkdir folder_hello` returns an empty Name and a 1600-12-31 LastWriteTime because read_directory rejects non-"*" patterns and FileInfo timestamps are zero. This plan fixes the WinFsp adapter and storage metadata API and re-runs the Hyper-V verification.

Output: Updated storage namespace format with timestamps, updated WinFsp filesystem adapter with pattern matching and notifications, passing cargo tests, and a passing SC-04 UAT entry on LAB-CLIENT01.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Encrypted namespace record -> store loader | Previously persisted metadata crosses a trust boundary; malformed records must be rejected. |
| WinFsp callback -> user-mode filesystem | Untrusted Windows callers supply file names and patterns; parsing and matching must stay bounded. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-26-01 | Tampering | `LocalEncryptedStore::load_namespace` | high | mitigate | Strict `dlp-namespace/v2` record parsing; reject malformed rows via `StorageError::IntegrityFailure`; preserve namespace integrity evidence before failing; accept only `v1` with safe current-time conversion. |
| T-01-26-02 | Denial of Service | `read_directory` wildcard matcher | medium | mitigate | Match patterns only against bounded entry names (max 128 bytes) already loaded in memory; no recursion or backtracking; `?` consumes exactly one UTF-16 code unit equivalent. |
| T-01-26-03 | Information Disclosure | `FileInfo` timestamp population | low | accept | Timestamps are file-system metadata, not protected content; they are exposed by normal NTFS semantics expected by D-11. |
| T-01-26-04 | Tampering | `winfsp` notify feature enable | low | accept | Feature is part of the already-approved `winfsp` 0.13.0 package; no new top-level dependency is introduced, so the existing lockfile and allowlist remain in force. |
</threat_model>
