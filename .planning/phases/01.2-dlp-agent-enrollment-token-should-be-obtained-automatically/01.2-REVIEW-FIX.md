### CR-01: Ordinary re-provisioning still mutates active authority state

**Files modified:** `crates/dlp-server/src/repository.rs`, `tests/windows/Invoke-AgentServiceSmoke.ps1`
**Commit:** d6799e2

**Applied fix:** Ordinary provisioning now locks and rejects an authority row with an active serial, explicitly rolls back the preceding allowlist write, and mints no token before that gate. ### CR-02: Equal-version cache poll can report success with missing selected bytes

**Files modified:** `crates/dlp-agent-core/src/config_cache.rs`
**Commit:** 901c6bc
**Status:** fixed: requires human verification
**Applied fix:** The equal-version/equal-digest path now validates exact cached bytes before returning `Unchanged`. A missing selected bundle is atomically restored from the already authenticated response and re-read before success; mismatched cached bytes fail closed as `CorruptPointer`. Restart and corruption tests cover durable repair and fail-closed behavior.

### WR-01: Enrollment token remains unguarded across early startup failures

**Files modified:** `crates/dlp-windows-service/src/service.rs`
**Commit:** e6bb22d
**Status:** fixed
**Applied fix:** Startup takes the token from the long-lived configuration on its first statement and holds the option in `Zeroizing` across credential-store, cache, and bootstrap-client construction. The token transfers to the enrollment coordinator only after all setup succeeds. Failure-path tests cover all three early construction stages.
