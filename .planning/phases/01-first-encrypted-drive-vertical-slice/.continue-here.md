## Critical Anti-Patterns

| Pattern | Description | Severity | Prevention Mechanism |
|---------|-------------|----------|---------------------|
| Cross-plan mega-commits | Committing changes from multiple plans in one commit breaks GSD atomicity and makes rollback/review impossible. | blocking | Classify every changed file by plan scope and commit each plan separately. |
| Debug logging in production paths | `eprintln!` and file loggers left in server routes/TLS leak diagnostics and are not part of any plan acceptance criteria. | blocking | Review every added log statement; remove or gate debug-only code before commit. |
| Rustfmt mixed with logic changes | Formatting noise obscures substantive diffs in code review. | advisory | Run `cargo fmt` separately and commit formatting before or after logic changes. |
| Uncommitted plan-spanning changes | Pending changes across multiple plans block downstream wave execution and risk losing work. | blocking | Complete reconciliation as the first resumed action; do not launch Wave 3 until `git status` is clean or changes are intentionally scoped to one plan. |
