## Trust Boundaries

| Boundary | Description |
|---|---|
| PostgreSQL selected policy -> signing provider | Transactional desired state becomes immutable signed bytes. |
| Network bundle -> endpoint cache/compiler | Untrusted bytes must pass identity, signature, replay, schema, digest, and resource checks before activation. |
| Trusted keyring -> key transition | New verification authority may be introduced only by established authority. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-02-03-01 | Tampering | Signed configuration activation | high | mitigate | Verify canonical signature, digest, audience, schema, version, action support, and ceilings before atomic pointer swap. |
| T-02-03-02 | Spoofing | Signing-key transition | high | mitigate | Require an already trusted key to sign a bounded unique-ID transition; reject self-introduction and conflicting IDs. |
| T-02-03-03 | Tampering | Concurrent activation/restart | high | mitigate | Atomically bind keyring, bundle, compiled-policy digest, current, and LKG generation; test concurrency and reopen. |
| T-02-03-04 | Denial of Service | Endpoint materialization | medium | mitigate | Compile only after bounded decode and enforce Plan 01 immutable endpoint ceilings before allocation/pointer swap. |
| T-02-03-SC | Tampering | Package supply chain | low | accept | This plan uses existing crypto/protocol dependencies and installs no package. |
</threat_model>
