# Phase 01.2 Plan 01: Automatic Enrollment Token Acquisition Summary

**PowerShell orchestrator now obtains the DLP_AGENT_ENROLLMENT_TOKEN from LAB-DC01 trusted provisioning, injects it into the DlpWindowsService environment, and cleans it up after enrollment without persisting the token on hungdinh-lt.**

## Performance

- **Duration:** 11m

- **Completed:** 2026-08-13T16:21:28Z
- **Tasks:** 3
- **Files modified:** 3

## Accomplishments
- Added `-EnrollmentTokenProvider TrustedProvisioning` and `-RetainEnrollmentToken` to `Invoke-Client01Runtime.ps1`.
- Implemented automatic trusted-provisioning invocation on LAB-DC01 with in-memory token capture and injection into `agent.env` / service registry Environment.
- Added token format validation (length <= 512, JWT-safe charset) that fails with `enrollment_token_invalid` before writing to LAB-CLIENT01.
- Added detection of existing `device.dpapi` credential to skip unnecessary re-provisioning.
- Added post-enrollment cleanup that removes `DLP_AGENT_ENROLLMENT_TOKEN` from registry Environment and `agent.env` unless `-RetainEnrollmentToken` is specified.
- Updated `HYPERV-DLP-STARTUP-GUIDE.md` and `ENV-VARS.md` to remove the manual token handoff and document the automatic flow.

## Decisions Made
- Retained `Manual` as the default `EnrollmentTokenProvider` so existing operator workflows continue unchanged.
- Made token cleanup the default; only retain the token when `-RetainEnrollmentToken` is explicitly supplied for troubleshooting.
- Validated token length and charset before any persistence to LAB-CLIENT01 to keep the install fail-closed.
