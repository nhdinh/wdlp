### `crates/dlp-log-debug-service/src/paths.rs` (utility, file-I/O)

**Analog:** none

No current crate authorizes filesystem paths. Implement the researched safe-core pattern: canonicalize the requested existing file and every configured allowed folder, then require `canonical_target.parent() == Some(canonical_allowed_folder.as_path())`. Reject relative targets, folders, nested descendants, sibling-prefixes, `..` escapes, and resolved symlink/junction escapes. Return an internal enum/error code only; `http.rs` chooses `forbidden_path` or `file_not_found`.

Do not add a marker, cache, watcher, or full-file read.

## Shared Patterns

### Workspace and dependency discipline

**Sources:** `Cargo.toml:1-22`, `crates/dlp-server/Cargo.toml:1-30`

Use workspace metadata and exact dependency pins. The new service remains an independent member—no `dlp-agent-core`, enrollment, management, health, or production package integration.

### Stable errors, no sensitive details

**Source:** `crates/dlp-server/src/lib.rs:26-49`

Map internal failures to enum variants and stable codes. At the HTTP edge, return short plain-text codes only (`invalid_tail`, `untrusted_client`, `file_not_found`, etc.); suppress `Display`/debug output for filesystem and OS errors.

### Actual connection identity

**Source:** `crates/dlp-server/src/routes.rs:183-194`

The existing server authorizes connection-provided metadata rather than HTTP headers. The debug service must apply the same boundary using the TCP peer `SocketAddr`, with loopback always accepted and remote access allowed only by valid configuration.

### Service lifecycle and shutdown

**Source:** `crates/dlp-windows-service/src/service.rs:294-435`

Use SCM control registration and explicit pending/running/stopped status transitions. Bridge `Stop` and `Shutdown` to the Axum server’s graceful-shutdown future, await completion, then report `Stopped`.
