## Verified discrepancies to resolve

| Contract area | Live evidence | Required correction |
| --- | --- | --- |
| Server database name | `ServerConfig::from_environment` reads `DATABASE_URL`; lab runners read `DLP_DATABASE_URL` and map it to `DATABASE_URL`. | Document direct consumer and orchestration alias separately. |
| Server listen default | Rust defaults `DLP_LISTEN_ADDRESS` to `0.0.0.0:8080`; the lab explicitly chooses `0.0.0.0:8443`. | Label 8443 as the lab override, not the binary default. |
| Endpoint timeouts | The service defaults polling/health/start/stop to `300/60/60/10`; initializer/example currently use `300/60/30/30`. | Align the catalog and docs to live service defaults unless an explicit lab override is clearly labeled. |
| Configuration key ID | The service default is `phase1-config-signer`; initializer uses `phase1-config-signing-key-v1`. | Distinguish binary default from explicit lab key ID and require server signer agreement. |
| Root CA representation | `AgentHttpClient::bootstrap` requires certificate PEM content; `Invoke-Client01Runtime.ps1` currently writes `DLP_ROOT_CA_PEM` verbatim even when it is a path. | Resolve inline-or-path input with the existing secret resolver, validate certificate content, deploy it, and persist the deployed path for the service. |
| Saved PEM values | The env-file readers are line-oriented `NAME=value` parsers, so multi-line PEM blocks cannot be stored directly. | Require PEM paths in env files; reserve inline PEM for process environment values and script handoff. |
| Enrollment token | The endpoint reads it optionally and trusted provisioning obtains it automatically; initializer currently prompts as if every catalog item is mandatory. | Encode and document conditional/optional requiredness. |
| PKI topology | The manual guide diagram shows admin/device CAs beneath the Phase 1 root, while rotation scripts create distinct self-signed CAs and TLS assigns separate peer roles. | Draw three distinct trust roles and verify only the chains that actually exist. |
| AD trust | Creating a standalone CA and importing only its root does not configure a domain controller for LDAPS. | Require export of the issuer of the active DC certificate, or a complete documented AD CS/DC certificate issuance procedure in its owning guide. |
| TLS verification example | The lab guide installs a global certificate-validation callback that accepts every server certificate. | Replace it with validation against `phase1-root-ca.pem` and the certificate hostname. |
| Toolchain | Workspace edition is 2024, while the guide says edition 2021. | State the repository value from `Cargo.toml`. |
