# Phase 01.2 Plan 01: Automatic Enrollment and Failure-Safe Token Lifecycle Summary

**Trusted provisioning is now the normal endpoint install path, with verified credential reuse/replacement, dual-location token cleanup, and live signed-policy activation.**

## Accomplishments

- Made `ServiceInstall` obtain a trusted-provisioning token automatically when no usable `device.dpapi` exists and skip provisioning when the credential is reusable.
- Added preview-only force behavior and Apply-gated replacement while preserving service, binaries, data, and cache.
- Removed the enrollment token from both `C:\dlp\agent\agent.env` and the service registry environment after success and after failed handoff.
- Required and proved `active_policy_version=1` and `active_policy_state=Active` in both initial/reuse and replacement live scenarios.
- Repaired the authenticated configuration path by canonicalizing DER serial bytes, aligning the configuration signer key ID, and populating/backfilling `device_allowlist`.
- Replaced full certificate/readiness dumps with sparse output and bounded opt-in diagnostics; the health probe now validates the server DNS name with the explicit lab CA.

## Deviations from Plan

### Auto-fixed Issues

**1. Removed verbose certificate/readiness output and trust-all behavior**

- Normal output previously included full public moduli and complete readiness objects.
- Certificate validation output is now suppressed unless diagnostics are requested; readiness emits only bounded booleans.
- The endpoint probe uses `curl --cacert` with DNS validation and lab-only disabled revocation lookup rather than a trust-all callback.

**2. Repaired protected configuration authorization and persistence**

- DER encoded a positive UUID serial with a leading sign-padding byte, while PostgreSQL stored the original 16 bytes.
- TLS identities and new ledger serials now share a canonical representation, with a regression test.
- Trusted provisioning now upserts `device_allowlist`; migration `202608280004` backfills existing enrollment authority rows.
- Server and Windows-service configuration signer key IDs now share `phase1-config-signing-key-v1` by default and support `DLP_CONFIGURATION_KEY_ID`.

**3. Updated migration-count contracts and smoke stream capture**

- DC01 migration proofs and the E2E ordered-migration list now expect four forward migrations.
- The live smoke wrapper captures PowerShell's information stream so status proofs are asserted rather than merely printed.

## Lab Repairs Performed

- Replaced the stale `C:\dlp\secrets\ad-ca.pem` fixture with the actual lab AD CA certificate and deployed it to LAB-DC01; LDAPS verification succeeds for both domain controllers.
- Reset the lab-only `svc_DLP_bind` account password to the runtime secret and enabled/unlocked the account; authenticated LDAPS bind succeeds.
- These were runtime lab-state repairs only and are not repository content.
