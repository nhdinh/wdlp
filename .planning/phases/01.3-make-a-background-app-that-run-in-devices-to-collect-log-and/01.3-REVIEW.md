# Phase 01.3: Code Review Report

**Reviewed:** 2026-08-23T05:30:00Z
**Depth:** standard
**Files Reviewed:** 13
**Status:** issues_found

## Summary

The phase-local debug service has three ship-blocking defects. Dispatcher startup failures exit successfully, pathname authorization is separated from the eventual file open by an exploitable replacement race, and every SCM status-reporting result is discarded even though a failed transition can leave a live network listener that SCM does not consider running or stoppable. Query rejection classification is also inaccurate. The portable suite passes (13 tests) and Clippy reports no warnings, but those checks do not exercise Windows SCM behavior or adversarial filesystem replacement.

## Critical Issues

### CR-01: Windows dispatcher failure exits with a success status

**Classification:** BLOCKER
**File:** `crates/dlp-log-debug-service/src/main.rs:5-8`
**Issue:** Windows `main` returns `()`. If `run_scm_service()` fails, the program prints `service_dispatcher_failed` and then returns normally, producing process exit code zero. Deployment scripts and supervisors therefore cannot distinguish dispatcher registration failure (including launching the executable outside SCM) from successful service termination. This contradicts the crate's stable nonzero lifecycle-failure contract.
**Fix:** Return `std::process::ExitCode` from the Windows `main`; return `ExitCode::FAILURE` when dispatcher startup fails and `ExitCode::SUCCESS` only after a successful dispatcher lifetime. If stable numeric dispatcher codes are required, call `std::process::exit` with a documented nonzero code.

### CR-02: Path authorization is invalidated by a filesystem replacement race

**Classification:** BLOCKER
**File:** `crates/dlp-log-debug-service/src/paths.rs:56-65`
**Issue:** `authorize_requested_file` canonicalizes and validates a pathname, returns that pathname, and `read_bounded_tail` reopens it later at `tail.rs:22`. Between validation and open, a user able to mutate an allowed log directory can replace the validated file or an ancestor with a symlink, junction, or other reparse point. The later open then resolves the path again and can read a file outside the authorized direct-child folder. Canonicalization followed by a separate pathname open is not an atomic authorization boundary.
**Fix:** Open the requested file once using platform protections appropriate to reparse points, validate the opened handle's final path and file type against the canonical authorized directory, and tail from that same handle. Do not return a pathname that must be reopened after authorization.

### CR-03: SCM status failures are ignored while the listener continues running

**Classification:** BLOCKER
**File:** `crates/dlp-log-debug-service/src/service.rs:78-81`
**Issue:** All four calls to `set_service_status` (lines 78, 104, 113, and 129) discard their `Result`. Most seriously, after binding `0.0.0.0`, a failure to publish `Running` at line 104 is ignored and the HTTP listener is served indefinitely. SCM may still regard the service as start-pending or failed, and its stop lifecycle is no longer dependable, while the debug endpoint remains exposed on every interface. Stopped/error transitions can likewise be lost without affecting the returned path.
**Fix:** Check every status update. Treat failure to publish `StartPending` or `Running` as startup failure, close the listener, log a stable redacted code, and return. During shutdown, propagate or at least deterministically record failure to publish `Stopped`; centralize transitions in a helper returning `Result` so no call can be silently discarded.

## Warnings

### WR-01: Every query-deserialization failure is mislabeled as an invalid tail

**Classification:** WARNING
**File:** `crates/dlp-log-debug-service/src/http.rs:158`
**Issue:** Any `QueryRejection` becomes `HttpError::InvalidTail`, including duplicate `path` fields and other malformed query shapes unrelated to `tail`. Clients receive a misleading stable code, and the documented error contract depends on Serde's aggregate rejection rather than the invalid field.
**Fix:** Deserialize a raw query representation and validate `path` and `tail` independently, mapping path/query-shape errors to `invalid_path` and only tail parse/range failures to `invalid_tail`.
