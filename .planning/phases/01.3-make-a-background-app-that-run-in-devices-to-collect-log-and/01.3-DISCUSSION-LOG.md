---

## Process Ownership

| Decision | Alternatives considered | Selected |
|----------|-------------------------|----------|
| Runtime owner | Existing DLP service; separate Windows service; per-user process | Separate development-only Windows service |
| Installation | Repository script; manual commands; lab provisioning | Manual Windows commands |
| Failure coupling | No effect; DLP health warning; stop dependent services | No effect on DLP |
| Code organization | Workspace crate; standalone `tools/` project; existing executable mode | Dedicated workspace crate excluded from production packaging |

**User's choice:** Keep the service separate and outside the ecosystem because it is needed only during development.

---

## HTTP Access Boundary

| Decision | Alternatives considered | Selected |
|----------|-------------------------|----------|
| Listener binding | Loopback; all interfaces; configurable loopback default | All interfaces |
| Remote access control | Bearer token; none; mTLS; trusted source IP | Configurable trusted-client IP allowlist |
| Configuration source | Environment variable; local file; Registry | Local configuration file |
| Invalid configuration | No listener; localhost-only; unrestricted | Localhost-only fallback |

**User's choice:** Permit remote lab access only from configured trusted client IPs, while preserving local access if configuration is unusable.

---

## Log Collection and Retention

| Decision | Alternatives considered | Selected |
|----------|-------------------------|----------|
| Source selection | Fixed DLP logs; Windows Event Logs; general configured sources; requested file | Client-requested file within an allowlisted folder |
| Folder matching | Recursive descendants; direct children; explicit files | Direct children only |
| Retention | None; bounded cache; archive | Read and return; keep nothing |
| Large files | Bounded tail; full file; byte ranges | Bounded tail snapshot |

**User's choice:** The client supplies the file, the configured folder allowlist constrains it, and the service keeps no data.

---

## Debugging API Contract

| Decision | Alternatives considered | Selected |
|----------|-------------------------|----------|
| Request | GET query; POST JSON; folder alias route | `GET /logs?path=<absolute-path>&tail=<line-count>` |
| Success body | JSON; text plus metadata headers; plain text | Plain text only |
| Byte-cap behavior | Silent newest-line subset; marker; reject | Newest complete lines without marker |
| Errors | Short code; detailed OS error; always 404 | HTTP status plus short plain-text code |

**User's choice:** Keep the endpoint simple for development clients and avoid leaking local filesystem details.
