## Trust Boundaries

| Boundary | Description |
|---|---|
| Provisioning DTO → PostgreSQL authority | Untrusted identity, digest, token, and AD fields must become one constrained record without plaintext secret retention. |
| Enrollment observation/CSR → issued credential | Endpoint input is untrusted until exact allowlist, dual-DC, token, fingerprint, and CSR checks pass. |
| Replacement transaction → protected routes | A split revocation/activation commit could leave two accepted credentials or no recoverable identity. |
