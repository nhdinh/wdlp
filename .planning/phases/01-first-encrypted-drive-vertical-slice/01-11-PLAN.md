<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| SCM/WTS event + session token → mount actor | Event ordering and user identity determine store authority. |
| Captured SID → per-user key/store | Identity confusion or broad key ACL can expose another user's data. |
| Mount actor → target session drive namespace | Letter collision or wrong-session mapping can displace/expose volumes. |
| User-session host → service-owned storage named pipe | A forged/stale/wrong-user host can attempt to select another SID/session/store or replay storage requests. |
| Sign-out/service-stop → callbacks/store | Races may accept new opens, leak keys, or leave a mount active. |
