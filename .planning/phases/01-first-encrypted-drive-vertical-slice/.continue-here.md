# Continue Here — Plan 01-21 Task 2 (Final Verifier + Independent Review)

## BLOCKING CONSTRAINTS — Read Before Anything Else

- [ ] CONSTRAINT: Per-user mapped drives are only visible in the interactive console session — PSRemoting sessions cannot see `P:`. Any harness that verifies the protected drive must use `Register-ScheduledTask -LogonType Interactive` or an equivalent interactive-session proxy.
- [ ] CONSTRAINT: `active_session_ids()` in `dlp-windows-service` must filter to real interactive user sessions (console session or sessions with a username). Enumerating all `WTSActive`/`WTSConnected` sessions launches `dlp-drive-host.exe` in the services session and the drive is invisible.
- [ ] CONSTRAINT: The Windows service must stay alive when the configuration verifier or transport is unavailable; early returns terminate the service and drop the drive.
- [ ] CONSTRAINT: `config/lab.phase1.example.yaml` uses `developer_orchestrator` for `hungdinh-lt`; the old `developer_host` value breaks privilege-manifest validation.

**Do not proceed until all boxes are checked.**

## Critical Anti-Patterns

| Pattern | Description | Severity | Prevention Mechanism |
|---------|-------------|----------|---------------------|
| PSRemoting drive probes | Using `Invoke-Command -VMName` to check `P:` fails because remoting sessions cannot see per-user mapped drives. | blocking | Always route protected-drive verification through interactive-session scheduled tasks or `psexec -i`. |
| Wrong WTS session selection | Enumerating all active WTS sessions includes session 0 and services sessions. | blocking | Filter to console sessions or sessions with a non-empty username before launching `dlp-drive-host.exe`. |
| Service loop early return | Returning from `run_service_loop` on verifier/transport failure stops offline enforcement. | blocking | Log warnings and keep the reconciliation loop running; poll only when components are healthy. |
| Role name drift | `developer_host` vs `developer_orchestrator` breaks automated manifest validation. | advisory | Treat `config/lab.phase1.example.yaml` as a contract file; update all consumers together. |
