<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| WTS/SCM event + token → session actor | Event order and token identity determine user/store authority. |
| User-session host → service-owned named pipe | Forged, stale, wrong-user, or malformed clients may attempt to cross identity/store boundaries. |
| WinFsp callbacks → authenticated store | Untrusted names, buffers, offsets, flags, concurrency, and cancellation must preserve durable/integrity semantics. |
| Sign-out/restart/reboot → keys/mount/store | Races can leave mounts, credentials, handles, or partial data active. |

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |

| T-01-15-01 | Spoofing/Elevation | session identity | high | mitigate | TokenUser-derived immutable session/SID, idempotent actors, no caller identity/store selector, adjacent/empty/concurrency tests. |
| T-01-15-02 | Spoofing/Elevation | storage IPC | high | mitigate | Service-owned DACL plus connecting SID/session/PID/actor-generation validation and bounded versioned messages. |

| T-01-15-04 | Tampering/Information disclosure | WinFsp callbacks | high | mitigate | Captured identity, bounded paths/offsets, authenticate before copy, durable commit before success, stable error mapping. |

| T-01-15-07 | Information disclosure | health/evidence | medium | mitigate | Stable codes/opaque digests and machine-tagged marker scans; no raw SID/path/key/content. |
