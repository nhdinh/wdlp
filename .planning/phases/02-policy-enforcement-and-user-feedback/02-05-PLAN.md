## Phase Goal

**As an** authorized Windows user, **I want to** have protected-drive operations evaluated against assigned policy with clear feedback, **so that** sensitive files remain inside the organization’s DLP boundary.

<objective>
Make the Windows service the authoritative decision-event, notification-intent, and Proceed-once grant boundary with exact per-user authenticated IPC.

Purpose: Warn feedback is security-sensitive authorization, so the companion must remain a renderer while the service owns identity, binding, expiry, consumption, invalidation, and evidence.
Output: Event transport, privacy projection, authenticated companion protocol, bounded grant registry, and deterministic multi-session/replay/concurrency tests.
</objective>

## Trust Boundaries

| Boundary | Description |
|---|---|
| Drive host -> Windows service | Decision/event and retry authorization cross a privileged process boundary. |
| Per-user companion -> service pipe | Untrusted interactive input must be bound to kernel-authenticated SID/session. |
| Service event -> notification projection | Rich enforcement metadata is minimized before reaching interactive UI. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-02-05-01 | Spoofing | Companion pipe identity | high | mitigate | Purpose-limited DACL, kernel client PID, impersonated token SID/session, and no claimed identity fields. |
| T-02-05-02 | Elevation of Privilege | Proceed-once grant | high | mitigate | Exact full binding, 120-second TTL, atomic compare/remove, one-use, bounded registry, and lifecycle invalidation. |
| T-02-05-03 | Tampering | Event/dedupe ordering | medium | mitigate | Record event before presentation dedupe and test concurrent attempts versus event counts. |
| T-02-05-04 | Information Disclosure | Notification model/IPC | high | mitigate | Project allowlisted safe fields only; opaque challenge carries no identity/path/rule authorization facts. |
| T-02-05-05 | Denial of Service | Intent/grant/dedupe registries | medium | mitigate | Hard bounds, monotonic expiry, deterministic eviction, bounded frames, and fail-closed absence. |
| T-02-05-06 | Tampering | Multiplexed drive actor channel | high | mitigate | Authenticate actor identity once, tag and bound every frame, correlate unique request IDs, keep policy updates distinct, block callbacks until exact response, and deny on timeout/disconnect/mismatch. |
| T-02-05-SC | Tampering | Package supply chain | low | accept | No package install or new external dependency is used. |
