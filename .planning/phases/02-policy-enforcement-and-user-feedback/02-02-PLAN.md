## Trust Boundaries

| Boundary | Description |
|---|---|
| Administrator/auditor mTLS peer -> policy API | TLS identity becomes a persisted server-side role; request role claims are untrusted. |
| Policy API -> PostgreSQL | Concurrent drafts, immutable versions, assignments, and status updates cross the transactional authority boundary. |
| Device mTLS peer -> desired/status routes | Device identity and monotonic deployment state must come from the authenticated certificate. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-02-02-01 | Spoofing | Administrator/auditor role | high | mitigate | Resolve issuer+fingerprint to persisted role after TLS verification; ignore all header/body role claims. |
| T-02-02-02 | Elevation of Privilege | Auditor mutation routes | high | mitigate | Separate inspection/mutation route layers and test every mutation with auditor credentials. |
| T-02-02-03 | Tampering | Immutable publication/assignment cursor | high | mitigate | Insert-only versions, unique constraints, transaction and row lock for publish/assignment/materialization. |
| T-02-02-04 | Repudiation | Deployment status | medium | mitigate | Bind reports to TLS DeviceId and monotonic desired/issued/activated versions with timestamps and stable errors. |
| T-02-02-05 | Information Disclosure | CLI/API errors and inspection | medium | mitigate | Project only policy metadata/validation findings; redact keys, samples, match excerpts, and internal errors. |
